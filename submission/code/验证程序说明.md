# 验证代码阅读与运行

## 验证程序

验证代码按数学任务组织为七个文件。阅读时先看各文件开头的流程说明，再看相应模型类与`main`入口；同目录的`验证公共接口.py`集中处理路径、JSON/CSV/压缩日志读写、数组加载、来源身份、数据校验和已有模型接口。

| 文件 | 负责的验证 | 直接复用的实现 |
| --- | --- | --- |
| `code/问题一舍入验证.py` | 温度与部分含水率的正确舍入、谱根隔离、解析区间和数值字段对表 | 共享文件与来源记录接口；严格谱算法独立实现 |
| `code/晚期区间验证.py` | 精确晚期初值、半离散误差管、连续样条屏障、指定时刻查询和局部轨迹生产 | 主模型构造、物性及数值右端 |
| `code/时间界限验证.py` | 332 h/763 h充分时间上界、累计下屏障及条件不可达性 | `code/深度研究/连续PDE.py`的有理向外算术 |
| `code/一维GLL验证.py` | 一维三次GLL独立弱式、九组求解及与FV场配对 | 数据和记录接口；弱式、物性保留独立实现 |
| `code/二维验证.py` | 解析/制造解、二维物理计算、全场比较、一维基准差及生产计划 | `code/深度研究/二维模型.py`的空间模型、时间推进、场记录和多项式区间算法 |
| `code/输入与假设验证.py` | 环境平台识别、24种单因素情景、物性与几何交叉及精度比较 | 主模型、边界、物性、事件求解和移动半径采样 |
| `code/一维FV验证.py` | 一维有限体积制造解、守恒结构及固定半径退化检查 | 主模型的径向与收缩求解接口 |

下面是直接可用的证据检查命令，均在支撑材料目录执行：

```powershell
python -B code/问题一舍入验证.py --mode verify --out ../核验_问题一
python -B code/晚期区间验证.py --mode verify --out ../核验_晚期
python -B code/时间界限验证.py verify --out ../核验_时间界限
python -B code/一维GLL验证.py readback --out ../核验_GLL
python -B code/二维验证.py readback --out ../核验_二维
```

重新计算各项验证的入口如下：

```powershell
python -B code/晚期区间验证.py --mode weighted --case both --out ../晚期加权区间
python -B code/晚期区间验证.py --mode continuous-first --case both --out ../晚期连续首段
python -B code/时间界限验证.py upper --out ../安全时间上界
python -B code/时间界限验证.py lower --out ../条件不可达下屏障
python -B code/一维GLL验证.py solve --out ../GLL完整求解
python -B code/二维验证.py mms --out ../二维制造解
python -B code/二维验证.py plan --out ../二维生产计划
```

完整谱根、解析区间和连续全窗口的命令见下文。每个文件均提供`--help`。`--out`应指向整个支撑材料目录之外的新目录，计算轨迹和输出报告保存在该目录。

`code/data/验证数据`保存证书、精确初态、原始GLL数组和来源记录，目录层次对应这些证据内部的相对路径。`code/data/验证数据清单.json`核对实际数据；`来源源码索引.json`解释既有证据中的源码身份。每次运行另外记录当前各类验证、共享接口和实际主模型的源码身份。证明中的初始条件、数值数组及参数哈希均按各验证的约定核对。

问题一证书覆盖37,800个温度值及17,357个含水率值；晚期证书针对保存节点定义的初值问题；时间界限适用于正文声明的B0一维模型及正则性条件。GLL对照、二维制造解和保存场比较分别说明数值验证范围。

## 完整数学计算

以下命令在支撑材料目录执行。`python`应指向已安装`requirements.txt`依赖的解释器。

```powershell
python -B code/问题一舍入验证.py --mode runtime-check --out ../Arb运行检查
python -B code/问题一舍入验证.py --mode direct-check --out ../解析直接求值复核
python -B code/问题一舍入验证.py --mode reconstruct-roots --out ../谱根完整重建
python -B code/问题一舍入验证.py --mode regenerate-exact --out ../解析区间完整重建
python -B code/晚期区间验证.py --mode continuous-full --case both --out ../晚期连续全窗
```

完整谱根排零、解析区间、连续全窗口和二维大网格生产具有较大的计算量。记录会区分证据读回、局部检查和完整计算。输入输出的详细对应关系见上一级`支撑程序输入输出说明.md`。

## 自产晚期数据的调用顺序

```powershell
python -B code/晚期区间验证.py --mode produce --runs ../晚期主轨迹 --out ../自产晚期快照
python -B code/晚期区间验证.py --mode weighted --bundle ../自产晚期快照 --out ../自产加权区间
python -B code/晚期区间验证.py --mode uniform --bundle ../自产晚期快照 --out ../自产统一区间
python -B code/晚期区间验证.py --mode refined --bundle ../自产晚期快照 --uniform-base ../自产统一区间 --out ../自产细化区间
python -B code/晚期区间验证.py --mode continuous-full --bundle ../自产晚期快照 --out ../自产连续屏障
python -B code/晚期区间验证.py --mode query --bundle ../自产晚期快照 --certificates ../自产连续屏障 --out ../自产时刻查询
```

`--runs`示例中的`晚期主轨迹`是整理好的输入目录，直接包含`p23/`和`q4/`。分别从本次主计算的`计算工作/runs/endpoint/p23/finest_candidate/p23`及`计算工作/runs/endpoint/q4/finest_candidate/q4`取出`internal.npz`和`endpoint.json`放入对应子目录。该整理只复制数据；两个案例均来自同一组主模型与附件。

`--runs`内每个案例的`internal.npz`需要包含早于等号时刻前3600秒的检查点及近终点检查点。produce从这些检查点重新积分至报告时刻后2秒。`model-bindings`逐项核对包内证明快照与主模型；`arithmetic`独立检查区间运算及样条残差核。

## 数值验证的专项入口

`一维GLL验证.py checks`包含弱式、制造解与守恒观察器检查；`compare-rounding --runs 路径清单.json`对照三组网格/容差轨迹及论文表格。清单中`production`、`p23`、`q4`的路径以该JSON所在目录为基准。

`二维验证.py`提供`checks`、`audit-check`、`fv-analytic`、`backend-check`、`heat-check`和`fixed-heat`专项检查。`physical`负责实际FE/FV场，`compare`负责连续重构场差，`plan --full-matrix`生成完整生产矩阵。任务参数及输入目录结构见各文件`--help`和《支撑程序输入输出说明》。

环境与假设情景集中于`输入与假设验证.py`，一维有限体积专用制造解集中于`一维FV验证.py`。先运行`输入与假设验证.py checks`可复核平台算法及边界参数；完整情景计算与输入关系见上一级《支撑程序输入输出说明》。

验证数据中的推导与运行记录保留生成时的路径语境。当前程序路径与调用方式以`code/验证程序说明.md`及《支撑程序输入输出说明》为准。
